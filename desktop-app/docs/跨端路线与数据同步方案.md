# 跨端路线与数据同步方案（决策稿）

> 第十五轮产出的讨论稿。目的：在动手写任何跨端代码之前，先把两个必须拍板的事定下来——
> **① 用哪条技术路线重写 ② 数据怎么跟着人走**。
> 结论先行：**推荐 PWA/Web 路线 + 云数据库同步（方案 B）**；PC 多设备同步可以先用**方案 C（零开发）**过渡。

---

## 1. 现状盘点：哪些资产能带去跨端

| 资产 | 位置 | 可迁移性 |
|---|---|---|
| 数据模型（events/tasks JSON） | `%APPDATA%\MyScheduleWidget\schedule.json` | ★★★ 字段即 schema，直接用 |
| 设计令牌（23 色键 ×2 主题） | `design/tokens.json`（本次已沉淀） | ★★★ 直接变 CSS 变量 |
| 语言表（300 键 ×2 语言） | `design/lang.json`（本次已沉淀） | ★★★ 直接用，`{0}` 占位符两端通用 |
| 布局/交互逻辑 | Views/Views2/Care 的 PowerShell | ✗ 随 WPF 淘汰，但**行为规格**可参考 |
| XAML 界面 | Ui.ps1 | ✗ 重写 |
| 测试思路（126 条审计断言） | ScheduleWidget.ps1 审计区 | ★★ 断言逻辑可移植成新端的测试 |

**红线：PowerShell 5.1 + WPF 只存在于 Windows 桌面。** 平板/手机不是"移植"，是"重写"。

## 2. 技术路线三选一

| | A. PWA / Web（推荐） | B. .NET MAUI | C. Flutter / RN |
|---|---|---|---|
| 一份代码覆盖 | PC+平板+手机（浏览器） | Windows+Android+iOS | Android+iOS（桌面弱） |
| 与现有资产契合 | tokens/lang 直接用 | 数据逻辑可译成 C# | 全部重写 |
| 离线能力 | Service Worker + IndexedDB | 原生 | 原生 |
| 托盘常驻/开机自启 | 弱（浏览器通知替代） | 强 | 弱 |
| 学习/迁移成本 | 最低 | 中 | 中高 |
| 安装体验 | 免安装（发链接） | 装包 | 装包 |

判断依据：这个工具是**个人日程**，核心诉求是"数据跟着人走 + 随手可看"，不是重客户端能力。
PWA 在 PC 上牺牲"托盘常驻"（现有 WPF 版继续承担桌面场景），换来平板/手机零门槛——两条线并存，各管一段。

**建议的分工**：WPF 版继续作为"桌面主力"（托盘/悬浮窗/离线本地数据），PWA 版作为"跨端入口"（平板/手机/任何浏览器），两者通过同一个云端数据集互通（见下）。

## 3. 数据同步方案（必须先拍板）

### 方案 A：不同步（现状 + 已实现的导出/导入）
- ✅ 零成本，已落地（主菜单「…」→ 导出/导入数据）
- ❌ 换设备要手动；多设备并行改动会互相覆盖

### 方案 C：零开发过渡——把数据目录放进同步盘
- 把 `%APPDATA%\MyScheduleWidget\schedule.json` 放进 OneDrive/坚果云等同步文件夹（可做设置项"自定义数据目录"或文档说明 junction 链接方法），多台 PC 自动同步。
- ✅ 今天就能用，不用写一行代码
- ❌ 只有 PC 能享；平板/手机没有同步盘；冲突时靠文件级"最后写入赢"

### 方案 B：云数据库 + 账号（正式方案，推荐）
- events/tasks 存云端（Postgres 类），客户端本地缓存 + 离线写、在线合并
- 客户端三端共用：WPF 版加一个"云同步开关"，PWA 版原生就是云的
- 可用现成托管服务（免运维、免服务器）：WorkBuddy 云服务 / Supabase 类（数据库 + 邮箱/微信登录 + 文件存储），或国内可直连的同类
- 同步策略建议：**单用户、按记录时间戳 last-write-wins**（日程/任务没有多人协作诉求，不需要 CRDT 那套）
- 成本：数据表 2 张 + 登录 1 套 + 每端一个同步模块

### 方案 D：自建后端
- 只有当 B 的托管服务不满足（数据合规/内网）才考虑，个人工具不建议自找运维。

## 4. 数据模型（跨端的契约，从现有 JSON 固化）

```jsonc
// schedule.json —— 跨端唯一数据契约（导出/导入、云同步、PWA 全部认它）
{
  "events": [{
    "id": "hex",           // 必填，客户端生成
    "date": "yyyy-MM-dd",  // 必填
    "start": 540,          // 分钟数 0-1440
    "end": 600,
    "title": "...", "tag": "work|focus|life|<自定义>", "note": "", "done": false,
    "repeat": {...},       // 重复规则（存在时）
    "reminderMin": 10      // 0 = 不提醒
  }],
  "tasks": [{
    "id": "hex", "text": "...", "done": false, "due": "yyyy-MM-dd", "dueTime": "HH:mm",
    "tag": "task", "project": "", "estimatedMin": 0, "actualMin": 0,
    "priority": "high|medium|low", "reminderMin": 0,
    "subtasks": [{ "text": "...", "done": false }]
  }]
}
```

跨端改造建议：给每条记录加 `updatedAt`（同步时间戳）与 `deleted`（软删除标记）——这是同步的最小前提，**在 WPF 版里现在就可以加**，等 PWA 起步时数据已经"同步就绪"。
