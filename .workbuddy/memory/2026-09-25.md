### 挖出来的两个真 bug（都不是用户报的）

**bug A：`.GetNewClosure()` 把 `Get-Pal` 打成 CommandNotFound**
- 位置：`Views.ps1` 任务卡行内详情面板里的 `$addLine` 脚本块（原第 2007 行）
- 原因：`GetNewClosure()` 把脚本块复制进一个**新的动态模块**，动态模块的函数表只有
  global 作用域；而 `Get-Pal` / `New-Txt` 定义在脚本作用域 → 一律 `CommandNotFoundException`
- 为什么难发现：①不展开走不到；②只有双击才展开；③抛出点在 `Fill-Tasks` 的
  `Children.Clear()` **之后** → 任务列被清空且没重建
- 用户看到的现象其实是"双击没反应 + 整列任务都消失"
- 修法：去掉 `.GetNewClosure()`（该脚本块只在本作用域同步 `&` 调用，不需要闭包）

**bug B：函数参数命名为 `$Args`，与 PowerShell 自动变量 `$args` 冲突**
- 位置：`Get-EventSourceOf`、`Get-MouseClickCount`（ScheduleWidget.ps1）、
  `Test-ClickOnButton`（Views2.ps1）
- 原因：`$args` 是"未绑定参数数组"，同名参数在函数入口**被绑定器覆盖成 `@()`** ——
  实参传进来了，函数体读到的却是空数组；`$Args.ClickCount` 在 StrictMode 2.0 下直接抛，
  被 try/catch 吞掉后**静默降级**成兜底值
- 实测证据：`verification\_args_probe.txt`
  ```
  param($Args) 读 .ClickCount -> THREW（在此对象上找不到属性）
  param($X)    读 .ClickCount -> 2
  ```
- 后果：`Get-MouseClickCount` 永远返回 1（所有双击分支失效）；
  `Get-EventSourceOf` 永远走不到 `OriginalSource`；`Test-ClickOnButton` 永远 false。
  周视图"双击编辑事件"+"空白拖拽新建"两条一起失效，而任务卡双击**恰好**走了
  `$script:SyntheticClickCount` 旁路先返回，把这个 bug 完整盖住
- 修法：参数统一改名 `$Evt`；`Get-EventSourceOf` 补齐
  `旁路 → OriginalSource → Source → $Fallback` 完整链路

### 本轮最重要的 3 个坑（都是"跑起来不报错、功能悄悄不对"）

1. **PowerShell 变量名大小写不敏感 → `$key` 覆盖 `$Key`**（最致命）
   `SetTabsShow` 形参 `$Key` 被循环里 `$key = $b.Tag['key']` 覆盖 → 四个页签只有第一个高亮。
   连着 7 轮加日志才定位（`dbg7` 暴露 `rawK=[window] Key=[appear]` 错位一格）。
   **教训：同一作用域里形参名和局部变量名不能只靠大小写区分。**

2. **`ControlTemplate` 烘焙底色 → 运行期改 `.Background` 无效**
   `New-PixBtn` 把底色写进模板字符串（`Background="$Bg"`），模板优先于控件属性，
   改了**不报错也不生效**。正确做法：`ApplyTemplate()` 后
   `Template.FindName('bd', $btn)` 改模板内 Border。已加进 `SyntaxCheck.ps1` 静态规则
   （跟踪变量来源，只有 `New-PixBtn` 造出来的变量才判红 —— 因为项目里 `$b` 多为
   `New-Bd` 造的 Border，改 `.Background` 完全正确）。

3. **下拉框"文案即取值"**
   `New-ComboField` 的 `.Text` 既是显示又是解析依据（`($cb.Text).ToLowerInvariant()`、
   `-like '5*'`）。本地化文案后解析**静默失效**。解法：新增 `New-ChoiceField`，
   语义值走 `.Tag`，解析处只读 `.Tag`。

   已用 `scope_test3.ps1` 实测证实机制。
2. `Get-EditorChrome` 加 `[switch]$NoSave`；×  落到第 1 列。**并删掉底部 Cancel**

   Esc 永远放弃。

### 本轮踩到的新坑（重要）
1. **`PSCustomObject` 没有 `Clone()`**。8.1 第一版写 `$hit[0].Clone()` → 运行期必失败
   （任务/日程是 `ConvertFrom-Json` 的产物）。异常被 try/catch 吞，表现是
   "勾选后 Ctrl+Z 没反应"，界面无提示。**修法：新增 `Copy-Record` 逐字段复制**，
   三处调用点（Care.ps1 Toggle-TaskDone、Views.ps1 Finish-WeekDrag、审计探针）统一改。
   这是本项目第 4 个静默失效类问题（前三：`$Key`/`$key`、ControlTemplate 底色、下拉框文案即取值）。
2. **断言别读对象引用**。`undo covers toggle and drag` 最初读 `$mid.done`，而 `$mid` 是
   数组里那个对象的引用，第二次 Toggle 原地改了它 → 永远测不出中间态。
   正确：立刻取布尔值 `$midDone = [bool](...)[0].done`。
3. **审计测试要清撤销栈**。前面若干条审计自己压过栈，不先 `Clear()` 就会弹出别人的条目
   （实测 `k1=task` 而非 `toggle`）。
4. **审计探针任务的字段名必须与真实一致**（`text` 而非 `title`），否则 StrictMode 抛
   "找不到属性 text"，`Push-Undo` 被吞。
5. **`pickershot` 会重开窗口**，按 `$script:Anchor` 重置月份 → 测试里必须"先翻月再截"。
6. 注释里不能写裸 `$script:变量名`（`SyntaxCheck` 静态规则会把注释也当读 → 误报）。
