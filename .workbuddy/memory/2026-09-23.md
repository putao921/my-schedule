**关键决策**：
1. 交付形态选 HTML 单文件原型（用户确认）。理由：像素风 + 三视图 + 响应式用原生 CSS/JS 最快，且零依赖可离线运行；后续迁 WPF/Electron 时 DOM 结构可直接对照。

4. 素材未直接引用图片文件，改用内联 SVG 图标 + canvas 绘制像素头像 —— 保证零外部依赖、可单文件分发。

**踩坑与修复**（重要，后续复用）：
- **`#body` 被整体清空导致 hero/日历条消失**：原实现 `el.body.innerHTML=''` 把 hero 和 calbar 一起删了。改为新增 `#view-root` 容器，只替换视图节点。这是「视图注入容器与静态头部混用」的典型错误。
- **flex 布局中视图节点顶掉头部**：`.month__grid` 的 `grid-auto-rows: minmax()` 有固有高度，会回传给 `.body`。解法：视图根节点加 `overflow:hidden` + `min-height:0`，切断固有尺寸回传。
- **Chrome `--headless=new` 的 `--window-size` 有最小宽度限制**（390 被抬到 504），导致手机截图失真、误判有横向溢出。**正确做法：用 CDP `Emulation.setDeviceMetricsOverride` 强制视口**。
- **`ev.target.matches is not a function`**：键盘监听挂在 document 上，合成事件/非 Element 目标没有 `matches`。必须先判 `typeof t.matches === 'function'`。
- **nowline 绝对定位需要容器 `position:relative`**，且作为 grid 子项要确认脱离网格流。
- 手机端必须禁止工具条/月网格横向溢出：容器加 `min-width:0`、`grid-template-columns` 用 `minmax(0,1fr)`。

**验证方式**：Chrome 无头 + 自写极简 WebSocket 客户端直连 CDP（无需装 puppeteer/playwright）。覆盖 390×844 / 834×1112 / 1440×900 三档，月/周/列表/夜间；交互回归含视图切换、搜索、任务勾选、新建落库、主题切换、快捷键、日期选中、翻页、当前时刻线。**页面错误 0**。

## 桌面日程小工具（像素风）— WPF 桌面版完成

**产出**：`C:\Users\lenovo\WorkBuddy\2026-09-23-15-30-45\desktop-app\`
- 程序：ScheduleWidget.ps1 + Ui.ps1 + Views.ps1 + Views2.ps1 + Care.ps1（PowerShell 5.1 + WPF，零依赖）
- 交付包：`dist\`（Start-MySchedule.cmd / Install-DesktopShortcut.cmd / Uninstall.cmd / README.md / MySchedule\*.ps1）
- 验证：`verification\`（SyntaxCheck / ClosureScan / ClosureProbe1-3 / RunAudit / RunShots6 / RunTrace / RunShot）

**最终验收**：语法 0 错误；交互审计 26/26 PASS（RaiseEvent 真点按，非直调函数）；6 张截图（3 视图 × 2 主题）目视比对 HTML 原型通过。

**本轮新修的硬骨头**（全部实测定位，非推理）：
1. **WPF 处理器读不到创建函数的局部变量**（动态作用域，回调时函数作用域已销毁，StrictMode 硬抛且常被 catch 吞掉）。用 ClosureProbe 三连实测定论：
   - 局部变量：Click / Tick 都取不到；
   - `$script:` 限定名：可见；脚本顶层变量（含 param，**不带限定名**）：可见；
   - 函数查找：可见（处理器里能调自定义函数）；
   - **`GetNewClosure()` 不可用**：会把处理器隔离进新模块，连脚本作用域的函数都找不到。
   解法 = 把处理器用到的局部变量整函数改名到 `$script:`（写了个行区间整词改名工具 Rename-InRange.ps1）。ClosureScan v2 已做成可复用的静态验收工具。
2. **`Get-EditorChrome` 参数类型写成 `Control`**：StackPanel 继承自 Panel（Panel→FrameworkElement→UIElement），不在 Control 链上 → 两个独立窗口**从来没能构建成功**。改 `FrameworkElement`。
3. **主题切换整窗重建在 WPF 里走不通**：`Application` 是在主窗口建好之后才 new 的，主窗口没进 `Application.Windows`；只要集合里有过窗口，新 Window 的 `Show()` 会**静默失败**（无异常、IsLoaded 恒 false、0x0），先关旧窗再 Show 反而连第一次都失败。**正解 = 换皮不换窗**：新树建在临时 Window 上，把 `Content` 过户给现有窗口（Window 级钩子只挂一次，用 `$script:LifecycleHooked` 防重复）。注意：复用判断必须用**进函数时就抓下的旧引用**，因为 `Build-Window` 早早就 `$script:MainWindow = $w` 覆盖了。
4. **`ShutdownMode` 必须显式 `OnExplicitShutdown`**：默认 `OnLastWindowClose` 会因为"关掉一个子窗口集合就空了"直接把整个应用关掉（表现为关一下编辑窗口程序就退出）。退出改由 Closed 处理器统一 `App.Shutdown()`（要退出必走 Closed；留托盘走 `Hide()` 不触发 Closed）。
5. **重建期间用 `$script:Rebuilding` 让旧窗口的 Closing/Closed 让路**，否则会弹确认框 / 误写设置 / 误 Shutdown。
6. **像素按钮的底色在 ControlTemplate 的 `bd` 边框上**（`$Bg` 构建时拼进模板字符串），改 `Button.Background` 无效；重画要 `ApplyTemplate()` + `Template.FindName('bd', $b)` 改边框背景 + 改 `Content`（TextBlock）的 Foreground。
7. **给按钮存自定义属性（如 `$b.TagColorKey`）会抛"在此对象上找不到属性"**，且整个窗口都建不起来。共享数据走 `$script:`。

**打包要点**：`.cmd` 启动器带 `-NoProfile -ExecutionPolicy Bypass -File`（只作用于本程序）；单实例互斥锁 `Local\MyScheduleWidget_<用户名>`（TestMode 不加锁）；数据 `%APPDATA%\MyScheduleWidget`（每账户隔离）；首次运行生成 `使用说明.txt`。`.cmd` 内容全 ASCII（OEM 代码页会弄乱中文），中文说明放 UTF-8 BOM 的 README.md。

**方法沉淀**：先探针定结论、再动代码（ClosureProbe 三连避免了按直觉大改）；运行时验收必须用 RaiseEvent 真点按；`verification\Run*.ps1` 每次跑独立时间戳数据目录（沙箱禁递归删除），结果落文件再 Read（stdout 会被吞）。
